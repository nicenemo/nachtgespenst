Two interfaces

LVGL or the classic direct-drawing interface: the same keymap, two ways to draw it.

History. The screenshots and measurements on this page date from the time when both boards showed all pages. Since then the Core2 has become the presentation clicker and the CoreS3 the macro pad; the current screens are on the Pages and Clicker pages.

LVGL (the main branches)

The interface introduced on 12 November 2026: LVGL 9 with a Material icon subset, rounded tiles, captions under icons, modifier badges (Ctrl+Shift, Hyper) and a themed header. It redraws only what changes.

Classic (branch feature/classic-ui)

All classic screenshots, page by page →

The current firmware with LVGL removed: every feature of both boards is kept (BLE, USB, LED bars, serial protocol, tests), but the screen is drawn straight onto the display with plain tiles, text labels and arrow shapes, in the spirit of the very first version of the project (a Core2-only flat grid, May 2026). Because the CoreS3 has no hardware buttons, it gets a bottom bar for previous, Locks and next.

How they compare

Both interfaces were built from the same keymap and tested with the same serial test suite, then measured on the boards. A page is "drawn" when it is on the display: LVGL answers LAYER before it renders, so the time is LAYER plus SHOT minus the plain SHOT read-out.

LVGLClassic
Flash used (CoreS3)2.33 MB (35.5 %)1.65 MB (25.2 %)
RAM used (CoreS3)105 kB (32.0 %)73 kB (22.4 %)
Time to draw a page, CoreS3about 360 ms (260 to 480 ms)about 92 ms
Time to draw a page, Core2about 450 to 630 msabout 100 ms
Source429-line ui.cpp, icon table, 40 kB icon font, LVGL configuration378-line ui.cpp, no icon font
LookIcons, anti-aliased text, rounded tiles, pressed-state animationText labels, arrow shapes, flat tiles
TestsBoth pass the serial test suite on both boards; the classic interface needed no change to the protocol or the tests.

The classic interface is clearly faster to switch pages and uses about a third less memory; LVGL looks richer and leaves room for more widgets. The slow part of LVGL is building a page (creating up to 24 buttons and rasterising icon glyphs at run time), which can be improved with pre-rendered bitmap fonts and reusable tile widgets; that work is on the to-do list.
