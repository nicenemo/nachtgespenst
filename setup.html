Set-up

What you need

  • An M5Stack Core2 and/or CoreS3, ideally with the M5GO base for the LED bar.
  • A host with Bluetooth LE or a USB port: the CoreS3 works over both, the Core2 over Bluetooth.

Flash and pair

The firmware source is not public and there are no published firmware images yet, so there is nothing to build or download from this site.

Pair the board from the host's Bluetooth settings; it advertises as 🌙👻-c2 or 🌙👻-cs3. Over USB the CoreS3 simply appears as a keyboard.

The keymap

The pages are defined in the firmware: each page is a grid of keys with a title, a set of bindings and an LED colour. Changing them means changing and rebuilding the firmware.

Talking to the board

Both boards answer a plain-text command line on the serial port (see the shell manual). It is enough for automated tests and for taking screenshots of every page.

How it works

  • Generated HID vocabulary. The USB HID Usage Tables (extracted as JSON from the official PDF) are turned into usage constants and shortcut macros such as kp_A and cp_MUTE by a generator that renders templates; nothing in the generated vocabulary is edited by hand.
  • Binding model. A binding is a HID page, a usage, a modifier mask and a label. Chord helpers (lcs, lmeh, lhyp) wrap macros the way ZMK does.
  • Keymap and UI. The keymap holds the layers; the UI draws the current layer, handles touch, mirrors the host LEDs on the bar and dims the backlight after a minute of idleness.
  • HID transports. Reports go out over Bluetooth LE and, on the CoreS3, over USB, through a non-blocking press queue with release retry; the PREFER and ONLY commands choose which transport receives them.
  • Serial protocol. PING, INFO, STATE?, LAYER, TAP, KEY, SHOT, PREFER, ONLY: enough for automated tests and for the screenshots on these pages.
